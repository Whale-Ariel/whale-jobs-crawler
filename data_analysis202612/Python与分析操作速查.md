# Python与分析操作速查

示例中的 `jobs` 为职位主表；具体字段是否存在，取决于运行到了第几课。

## 表格与基础语法

| 写法 | 含义 | 注意 |
|---|---|---|
| `type(x)` | 查看对象类型 | 字符串中的JSON仍是字符串 |
| `d.get('title', '')` | 安全取字典字段 | 键存在且值为None时不会自动补空串 |
| `json.loads(text)` | JSON字符串→Python对象 | JSON也可能是列表，需要检查dict |
| `pd.DataFrame(records)` | 字典列表→表格 | 不同键对齐为列，缺少的键成为缺失 |
| `df.shape` | 行数、列数 | 一行代表什么由数据设计决定 |
| `df.head(5)` | 前5行 | 不代表随机样本 |
| `df.sample(5, random_state=42)` | 可重现随机抽样 | 不等于人工审核标签 |
| `df.loc[mask, ['title']]` | 按标签/条件选行列 | Series条件使用&、\|和~ |
| `df.iloc[:5, :3]` | 按位置选前5行前3列 | 切片右端不包含 |
| `df.copy()` | 独立副本 | 适合派生分析，保留原表 |

## 整理与分析

| 写法 | 含义 | 常见误用 |
|---|---|---|
| `s.isna()` | 检查缺失 | 不会把空字符串自动当缺失 |
| `s.fillna(0)` | 缺失补0 | 薪资、经验未知不能随便补0 |
| `s.astype(str)` | 类型转换 | 先考虑None是否应保留缺失 |
| `s.map(function)` | 每个元素执行函数 | 函数需要覆盖空值与异常类型 |
| `df.groupby('source').size()` | 组内总行数 | count只统计指定列非缺失值 |
| `df.groupby('source')['job_key'].nunique()` | 组内不同职位数 | explode后更应明确不同职位 |
| `df.sort_values('n', ascending=False)` | 排序 | 排序后索引不自动重建 |
| `df.explode('cities')` | 列表展开为行 | 一职位多城市导致多行 |
| `df.melt(...)` | 宽表转长表 | 行单位变成特征关系 |
| `left.merge(right, on=KEY, validate='one_to_one')` | 按键关联并检查基数 | 一对多直接相加会重复计职位 |
| `pd.crosstab(a, b)` | 两维交叉计数 | 与分母统一后的比例不是一回事 |
| `df.div(row_totals, axis=0)` | 按行索引对齐相除 | axis在不同函数中所指不同，需看具体操作 |

## 数组与文本

- `axis=0`在求和中沿行方向汇总，得到每列总和；`axis=1`沿列方向汇总，得到每行总和。
- 布尔值的 `sum()`是满足条件的数量；`mean()`是满足条件的比例。缺失处理会影响分母。
- `int8`可节省0/1存储，但矩阵聚合前转`int64`，防止计数溢出。
- `re.search`寻找命中；`re.finditer`遍历全部命中，可保留字符位置与证据。
- TF-IDF输入矩阵的行对应文本、列对应词项；不要打乱文本行序后按位置贴预测值。
- `fit`学习参数，`transform`沿用参数转换新数据；测试集只能transform/predict，不能fit。
- `Pipeline`把向量化与分类器封装，减少先在全数据学习词表造成的泄漏。

## 读代码时的五个检查问题

1. 输入是什么对象？字符串、字典、列表、Series还是DataFrame？
2. 一行代表什么？职位、地点关联、技能关联还是唯一文本？
3. 过滤后还用原来的分母吗？
4. 关联或展开后是否可能重复计数？
5. 输出是观察事实、规则提示、模型诊断量，还是未经验证的解释？
