**1. 核心职位表 `pending_jobs`**

实际建表语句：

```sql
CREATE TABLE pending_jobs (
    seq          INTEGER PRIMARY KEY AUTOINCREMENT,
    source       TEXT NOT NULL,
    portal       TEXT NOT NULL,
    batch_id     TEXT NOT NULL DEFAULT '',
    source_site  TEXT NOT NULL DEFAULT '',
    job_id       TEXT NOT NULL,
    payload      TEXT NOT NULL,
    enqueued_at  TEXT NOT NULL,
    version      INTEGER NOT NULL DEFAULT 1,

    UNIQUE(source, portal, batch_id, source_site, job_id)
);
```

| 字段 | 含义 |
|---|---|
| `seq` | 本地自增序号 |
| `source` | 公司来源，例如 `bytedance`、`alibaba` |
| `portal` | 招聘渠道标识 |
| `batch_id` | 招聘批次，没有时为空字符串 |
| `source_site` | 来源站点，例如阿里不同事业部 |
| `job_id` | 官网职位 ID |
| `payload` | 完整职位 JSON，实际存储类型为 `TEXT` |
| `enqueued_at` | 入队时间 |
| `version` | 队列记录版本，用于同步确认 |

五个身份字段组成唯一约束，防止同一职位重复入队。

`payload` 中的 48 个字段如下，按用途整理：

| 类别 | JSON 字段 |
|---|---|
| 职位身份与名称 | `job_id`、`type`、`title`、`sub_title`、`job_code` |
| 职位内容 | `description`、`requirement` |
| 职位分类 | `job_category_id`、`job_category_name`、`job_category_en_name` |
| 官网招聘类型 | `recruit_type_id`、`recruit_type_name`、`recruit_type_en_name` |
| 城市与地址 | `city_code`、`city_name`、`city_en_name`、`city_list`、`address`、`address_list` |
| 链接与标签 | `job_url`、`job_hot_flag`、`job_subject`、`job_function` |
| 部门与流程 | `department_id`、`job_process_id`、`storefront_mode`、`process_type` |
| 薪资与要求 | `min_salary`、`max_salary`、`currency`、`head_count`、`required_degree`、`min_level`、`max_level` |
| 时间 | `publish_time`、`expiry_time` |
| 来源及组织 | `raw_data`、`source`、`company`、`business_unit`、`business_units`、`organization_assignments`、`source_site` |
| 统一招聘类型与批次 | `recruitment_type`、`recruitment_name`、`batch_id`、`batch_name`、`program_tags` |

JSON 内可保存字符串、数值、数组、对象及 `null`；这些内部字段不受 SQLite 列级约束。

**2. 指纹表 `job_fingerprints`**

```sql
CREATE TABLE job_fingerprints (
    source        TEXT,
    portal        TEXT,
    batch_id      TEXT NOT NULL DEFAULT '',
    source_site   TEXT NOT NULL DEFAULT '',
    job_id        TEXT,
    fingerprint   TEXT,
    last_seen_at  TEXT,

    PRIMARY KEY(source, portal, batch_id, source_site, job_id)
);
```

用于保留职位的内容指纹和最近发现时间。职位同步出队后，仍可通过这张表判重。

**3. 组织关系表 `job_organizations`**

```sql
CREATE TABLE job_organizations (
    source           TEXT,
    portal           TEXT,
    batch_id         TEXT,
    source_site      TEXT,
    job_id           TEXT,
    circle_code      TEXT,
    department_code  TEXT,
    business_unit    TEXT,
    department_name  TEXT,
    work_cities      TEXT,

    PRIMARY KEY(
        source, portal, batch_id, source_site,
        job_id, circle_code, department_code
    )
);
```

一个职位可以对应多个组织或部门，所以单独存为多行关系。

```sql
CREATE TABLE recruitment_batches (
```

**索引和关联的实际情况**

- 只有主键、唯一约束自动生成的索引，**没有额外的业务查询索引**。
- **没有外键、视图或触发器**。
- 各表通过 `source + portal + batch_id + source_site + job_id` 等字段在逻辑上关联。
- 标题、城市等字段在 JSON 中，查询时需要提取。例如：

```sql
SELECT
    seq,
    source,
    portal,
    job_id,
    json_extract(payload, '$.title') AS title,
    json_extract(payload, '$.city_name') AS city_name,
    json_extract(payload, '$.job_url') AS job_url
FROM pending_jobs
ORDER BY seq DESC
LIMIT 20;
```
